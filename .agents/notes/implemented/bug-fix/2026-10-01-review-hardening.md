# Agent Note: 请求边界、凭据保存和缓存故障处理

Status: implemented

## Problem

服务允许用空签名访问配置为关闭的凭据接口；短查询、非 ASCII token 和 Redis 写入失败可触发 panic。限流按完整 token 计数，业务却截断 token。配置加载会回写并丢弃本地凭据。会员错误被永久保存为地区不可用，队列容量也没有限制正在执行的后台任务。

## Decision

- 凭据接口要求合法地区、显式地区开关和非空配置密钥。拒绝请求不读取 Redis。凭据响应禁止缓存，access key 严格校验 32 位十六进制格式。
- 签名解析使用末尾 `&sign=` 分隔符，不依赖字节偏移；保留上游要求的 MD5 签名协议。
- 限流基于无端口的客户端 IP，仅显式配置的可信代理可传递 X-Real-IP。默认不信任转发头。
- 普通配置加载只读。迁移支持 JSON、YML、YAML，保留新字段、凭据和未知字段，验证后备份旧文件。启动仅在 Redis 缺少凭据时初始化，保留已刷新的 token。
- Redis 缓存写入是 best effort，错误只记录警告；损坏缓存按未命中处理。地区判定区分可用、不可用和未知；新地区缓存键使用 1402，一小时过期，避开旧的永久错误数据。
- 后台最多执行 8 个任务；播放刷新在入队前取得按缓存键去重的 RAII guard，在队列拒绝、取消、panic 或完成时释放。有界队列不等待空位，避免后台任务自我入队产生死锁。
- TLS 显式启用时配置错误阻止启动，支持 PKCS#8、RSA、EC PEM，不输出私钥。诊断保留 UID、地区和错误信息，移除 token、带签名 URL、代理凭据和原始响应体。
- 港台 resign 传递请求地区，自定义 POST 使用配置正文。CI 执行测试和格式检查，使用 artifact v4；锁文件纳入版本控制以支持干净 checkout 的 --locked 检查。

## Alternatives considered

1. 保留按 token 限流并统一截断：能减少 NAT 用户共享额度，但未认证请求仍能轮换 token；选择 IP 基础限流并显式声明代理信任，代价是同出口共享额度。
2. Redis 写入失败时拒绝整个请求：能严格保证写入成功，但缓存不可用会连带拒绝已经取得的上游结果；采用 best effort，读取鉴权凭据仍维持原有鉴权流程。
3. 延续启动时回写配置：能自动补齐默认字段，但会丢失注释、未知字段和被跳过序列化的凭据；正常加载改为只读，版本迁移单独备份。
4. 用等待式 send 实现背压：能避免丢任务，但后台执行器自身也会生产任务，有形成等待环的风险；队列满时丢弃刷新任务，由后续请求重试。

## Consequences

反代部署必须配置 trusted_proxies，开放凭据接口必须设置非空 api_sign。旧的带后缀 token 不再被接受。后台负载有上限，但高负载可能延后刷新。缓存故障可能增加上游请求；安全认证失败不会因此自动变成认证成功。凭据仍保存在原配置和 Redis 中，本改动不引入新的秘密管理系统。

日志不再包含完整请求和响应载荷，诊断上游协议变化时信息更少。新地区缓存首次访问需要重新建立，旧键无需清空其他 Redis 数据。TLS 配置错误不会产生隐式 HTTP 服务。

## Verification

`cargo test --locked --target-dir target/review-hardening` 覆盖模拟 Redis/HTTP 凭据访问、拒绝请求不读凭据、参数错误、真实 Governor 限流、可信代理、Redis 断连、地区缓存、坏缓存、刷新去重及释放、后台并发与 panic 隔离、配置迁移、PEM 容器和自定义 POST 正文。测试仅访问本机临时端口，不调用真实账号或推送平台。

使用独立 target 目录，因为原 target/debug 下二进制正在运行；源码修复不会自动替换该服务。

OSV 扫描覆盖锁文件的注册表依赖，并在依赖升级后达到未解决项为 0，详情见 DEPLOY.md 第 13 节。`h2 0.3.x` 没有可直接采用的 0.4.16 补丁版本，因此在 `vendor/h2/` 回移官方修复并单独归档，而不是强行覆盖不兼容依赖、关闭协议或改写网络栈来掩盖告警。
